# AutoResearch 质量控制标准协议

> 版本 v1.0 | 最后更新 2026-07-20
> 本协议定义 AutoResearch 的 6 道质量 Gate 检查标准，所有 Gate 通过是论文进入编译输出的前置条件。

---

## 一、总则

AutoResearch 通过 6 道质量 Gate 对论文进行自动化质量检查。每道 Gate 输出：

- **状态**：pass（通过）/ warn（警告，建议修改）/ fail（不通过，必须修改）
- **分数**：0-100，反映该维度的质量水平
- **问题列表**：具体的问题描述和建议

**最低通过标准**：所有 Gate 状态为 pass 或 warn，无 fail。

---

## 二、G1 — 引用核验

### 检查内容

| 检查项 | 说明 |
|--------|------|
| 引用完整性 | 每个 `\cite{key}` 在 `refs.bib` 中是否有对应条目 |
| 交叉引用有效性 | 每个 `\ref{label}` 是否指向实际存在的 `\label` |
| 引用覆盖率 | 长度 > 500 字符的章节是否至少含有一条引用 |
| 参考文献文件 | 项目根目录是否存在 `refs.bib` |

### 评分规则

- 起始分 100
- 每个悬空引用 -5 分（上限 -50）
- 每个悬空交叉引用 -5 分（上限 -30）
- 每个长章节无引用 -5 分（上限 -20）
- 缺少 refs.bib -30 分

### 通过标准

- pass：≥ 70 分
- fail：< 70 分

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| cite key 不存在于 refs.bib | 添加缺失的 bib 条目，或修正拼写错误 |
| `\ref{fig:xxx}` 无对应 label | 在对应图片处添加 `\label{fig:xxx}` |
| 长章节无引用 | 为关键论断添加文献支撑 |
| refs.bib 缺失 | 在项目根目录创建 refs.bib 文件 |

---

## 三、G2 — 数据完整性

### 检查内容

| 检查项 | 说明 |
|--------|------|
| 图表引用完整性 | `\ref{fig:}` / `\ref{tab:}` / `\ref{eq:}` 是否有对应 label |
| Label 使用率 | 已定义的 `\label{fig/ tab/eq:}` 是否在正文中被引用 |
| 未解析引用 | 是否存在 LaTeX 编译产生的 `??` 标记 |

### 评分规则

- 起始分 100
- 每个悬空图表引用 -5 分（上限 -20）
- 每个未使用的 label -3 分（上限 -10）
- 存在 `??` 标记 -10 分

### 通过标准

- pass：≥ 70 分
- fail：< 70 分

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| 正文引用了不存在的图表 | 添加对应的 `\label`，或删除无效引用 |
| 定义了 label 但从未引用 | 在正文中引用该图表，或删除多余的 label |
| `??` 标记 | 重新编译 LaTeX（xelatex 两次），检查 label 拼写 |

## 四、G3 — 逻辑一致性

### 检查内容

| 检查项 | 说明 |
|--------|------|
| Abstract-Conclusion 术语重叠 | Abstract 和 Conclusion 的核心术语是否一致 |
| argument.md 覆盖度 | 论证结构中声明的论点是否在论文正文中体现 |
| 章节结构完整性 | 论文是否包含标准的 Introduction/Methods/Results/Conclusion |

### 评分规则

- 起始分 80（语义判断需 AI/人工辅助）
- Abstract-Conclusion 术语重叠 < 5 个 -20 分
- argument.md 主张在正文中缺失（每个 -10 分，上限 -30）

### 通过标准

- pass：≥ 60 分
- warn：< 60 分（提示人工审查）

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| Abstract 和 Conclusion 术语不一致 | 统一关键术语的表述 |
| argument.md 中的论点未写入正文 | 将缺失的论点补充到对应章节 |
| 缺少标准章节 | 添加 Introduction/Methods/Results/Discussion |

---

## 五、G4 — 过度声称

### 检查内容

| 检查项 | 说明 |
|--------|------|
| 绝对化词汇 | "first ever""never before""revolutionary"等 |
| 夸大修饰 | "dramatically""remarkably""strikingly" |
| 未限定的绝对词 | "optimal"（无具体约束条件）"always""never" |
| Introduction 承诺性表述 | "we will prove/show/demonstrate" |

### 评分规则

- 起始分 100
- 同种过度声称出现 > 2 次，每个 -3 分（上限 -30）
- Introduction 中的承诺性表述每个 -5 分

### 通过标准

- pass：≥ 60 分
- fail：< 60 分

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| 使用"first ever" | 改为 "to the best of our knowledge" 或附文献检索证据 |
| 使用"prove" | 改为 "demonstrate""suggest""indicate""provide evidence" |
| 使用"optimal"无约束 | 明确优化目标和约束条件 |
| "we will show" | 改为 "we show" 或 "this paper presents" |

## 六、G5 — 格式合规

### 检查内容

| 检查项 | 说明 |
|--------|------|
| LaTeX 基础结构 | `\documentclass`、`\begin{document}`、`\end{document}` |
| 元信息完整性 | `\title`、`\author` |
| 参考文献配置 | `\bibliography` 或等价命令 |
| 花括号配对 | `{` 和 `}` 数量是否一致 |
| 环境配对 | 每个 `\begin{env}` 是否有对应 `\end{env}` |

### 评分规则

- 起始分 100
- 缺少基础结构每项 -15 分
- 花括号不配对 -20 分
- 环境不配对 -20 分

### 通过标准

- pass：≥ 70 分
- fail：< 70 分

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| 缺少 `\documentclass` | 在 main.tex 首行添加 |
| 花括号不配对 | 检查嵌套结构，确保每个 `{` 有对应 `}` |
| 未闭合 environment | 添加对应的 `\end{env}` |

---

## 七、G6 — 隐私审查

### 检查内容

| 检查项 | 说明 |
|--------|------|
| 邮箱地址 | `\author{}` 或正文中的 email |
| 机构信息 | 大学/学院/研究所/实验室名称 |
| ORCID | ORCID 标识符 |
| 基金号 | 5 位以上数字（可能为基金编号） |

### 评分规则

- 起始分 100
- 每个邮箱地址 -10 分（上限 -30）
- 存在机构信息 -10 分
- 存在 ORCID -5 分
- 存在疑似基金号 -10 分

### 通过标准

- pass：≥ 70 分
- warn：< 70 分（提示人工审查）

### 常见问题

| 问题 | 修复方式 |
|------|---------|
| 盲审版本含作者邮箱 | 用占位符替换，投稿时再还原 |
| 盲审版本含机构名 | 替换为 "University X" 或删除 |
| 致谢含基金号 | 盲审时删除致谢部分，或匿名化基金号 |

---

## 八、质量承诺

点击"同意"即表示您确认：

> 我已了解 6 道质量 Gate 的检查标准和通过条件。
> 我将认真对待每条 Gate 提出的问题，逐项修复后再提交编译。
> 我理解自动检查不能替代人工审稿，Gate 通过不代表论文无质量问题。
